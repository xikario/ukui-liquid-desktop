# v0.5.1 · 系统监视诊断与多播放器接入

日期：2026-10-01。本次为 0.5 系列源码小版本，包含系统监视、音乐小组件及 v0.5.0 之后已合入的设置、材质与稳定性修复。

## 系统监视

诊断详情采用“诊断概览 / 详细分析 / 采样数据”三页，显示诊断对象、请求模型、时间和采样进度。命令独立显示用途、适用条件与风险，只支持复制；完整报告可复制或导出 TXT，固定采样快照可导出 JSON。诊断仍只提供建议，不执行命令或结束进程。

视图随状态变化更新，保留文本选择与滚动；错误状态隐藏旧结论。支持深浅配色与缓存液态背景，改善纯白壁纸下可读性。模型选择沿用全局液态菜单，自动获取的模型 ID 不可编辑，“自定义…”允许手写。空正文、截断或损坏 JSON 保留至多一次补取。

## 多播放器音乐

设置 → 音乐播放器：先手动打开一次支持 MPRIS 的播放器，再添加已运行客户端，识别启动程序、工作目录及桌面入口；已配置的客户端也可点击“从运行进程识别”。点击“应用”保存，不再弹出程序文件选择器。

只接入已启用配置，多个运行时优先选择服务所属进程启动最晚的客户端，退出后回到仍在运行的客户端。较旧播放器改变播放状态不会抢占连接。原有 Strawberry 配置保留，新发现的客户端不会自动启用。

X11 下“打开播放器”按当前服务所属进程身份定位窗口并恢复最小化，修复 YesPlayMusic 的前置请求无可见效果。进度、音量、异步状态与封面更新均绑定当前连接，防止切换时误操作其他客户端。

以上为本次功能的针对性回归，不代表重新执行所有历史用例；远端检查结果以本版本提交的 GitHub Actions 为准。

## 升级与边界

检出 `v0.5.1`，按 [构建说明](../BUILD.md) 重新构建，再按 [安装与恢复](../INSTALL_AND_RESTORE.md) 更新用户安装。Fences 核心及关于页为 0.5.1，其他组件保留独立版本号。公共模块为静态链接，更新后需重建依赖应用。GitHub 提供源码 ZIP / tar.gz，本次不附通用预编译安装包。

音乐客户端需要主动提供 MPRIS；定位、音量、前置能力取决于软件接口。X11 窗口恢复不代表完整 Wayland 支持。读取进程启动时间失败时按本次观察到的服务注册顺序回退，无法恢复未知历史。

本项目为用户态实现，保留既有用户布局、配置及第三方许可。发布文档中的“未提交/未推送”是此前本地实施阶段记录；本次用户已授权提交并发布 v0.5.1。
