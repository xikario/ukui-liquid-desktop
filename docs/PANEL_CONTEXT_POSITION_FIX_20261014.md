# 任务栏右键菜单跳到左上角：定位时序修复

日期：2026-10-14。

## 原因与实现

本机右键任务栏空白位置，原生菜单实际出现在 `(0,0)`，宽高为 327×663。隔离环境也确认同一时序：其他 Show 过滤器先改变已可见菜单的大小，重入 Resize；公共菜单适配器尚未处理 Show、初始化本次屏幕边界，就用空边界限制位置，从而将菜单移动到屏幕原点。

`MenuSkin` 增加本次显示的准备状态：显示前和隐藏后均清除，仅在背景捕获与材质准备完成后标为就绪。准备阶段的尺寸变动交由 Show 统一处理，屏幕边界有效后再约束最终位置；之后的 Resize 继续更新尺寸、材质和原生轮廓。隐藏时清除旧的屏幕与背景区域，避免重新打开使用上次的边界。

没有引入定位轮询或常驻定时器。悬停、材质、开合动画和三级菜单懒加载继续沿用既有路径。

## 回归证据

新增测试使用父窗口为 UKUIPanel 的原生 `QMenu::exec(globalClick)`，提前 polish 后安装 Show 布局过滤器，在 Show 期间执行一次 resize，明确断言该重入分支确实发生；随后检查菜单实际位置，并增加项目验证后续尺寸约束。

旧实现的测试失败，输出 `QRect(0,0 258x444)`，点击点为 `(1280,1410)`。修复后，1 / 1.25 / 1.5 / 2 倍缩放的 X11 任务栏回归全部通过。任务栏与公共模块共 49 项 CTest 的最终结果为 48 项通过、1 项 GPU 用例跳过；包含托盘行为、动态三级菜单、弹窗、控件和材质测试。全量初跑时，无显示器测试对菜单高度增长的断言过严，因小屏幕高度限制失败；改为验证实际宽度增长和屏幕边界后，该项单独复跑通过，四档 X11 检查的实现和定位断言保留。

## 本机安装与实测

安装前备份插件、任务栏配置和液态配置，更新用户插件并重启任务栏。会话管理器请求未停止该实例，因此只对已核验的旧任务栏 PID 发送 SIGTERM，确认退出后启动新实例，没有创建并行任务栏。

核验安装文件与构建文件哈希一致、运行映射对应新插件、只有一个任务栏进程，窗口几何、系统任务栏设置和液态配置保持一致。

在 2880×1800 屏幕上于 `(1750,1763)`、`(1850,1763)`、`(1950,1763)` 分别右键，菜单 x 为 1751、1850、1950，y 均为 1065，宽高为 327×663；菜单下边缘与任务栏上边缘对齐。1.5 倍缩放下首个 x 的 1 像素偏差来自逻辑坐标取整。外观子菜单也正常在相邻位置展开，未修改菜单选项。

本地证据位于 `apps/ukui-panel-liquid/build/artifacts/context-position-20261014/`，包括构建、失败复现、全量测试、单项复跑、部署检查和桌面菜单坐标记录；截图和日志不纳入 Git。
