## 开始菜单的原因与处理

原高光定时器在菜单显示期间每 33 ms 查询鼠标位置，移动时更新整圈 28 px 边缘。应用按钮的每次鼠标移动都会重绘图标和文字，左侧悬停切换还会更新整个菜单。

现在通过 Qt 鼠标事件更新目标位置，33 ms 定时器只在合并移动或高光收敛期间运行，收敛后停止。观察子控件事件但不拦截，搜索和视图切换后新建的控件也启用鼠标跟踪。控件光泽与边缘高光使用同一份事件位置，不在绘制时重新查询鼠标。

重绘覆盖旧、新高光的实际边缘范围，以及受径向光泽影响的搜索框、标题胶囊和侧栏局部。鼠标离开控件后仍会更新其受影响光泽，避免后续完整重绘突然改变旧高光。绘制时保留更新区域与圆角裁剪的交集；跳过范围外的侧栏图标和材质。应用按钮内部移动不再重复重绘，原有悬停动画、按压和拖拽逻辑保留。

菜单隐藏、换肤或重新打开时停止并清空高光动画。菜单外点击检测等其他已有机制继续运行；停止高光定时器不代表进程所有后台工作都被移除。

## 同环境 CPU 对比

使用修改前保留的二进制与本轮构建，在同一台机器的独立 Xvfb / D-Bus 会话中顺序采样。150% 缩放、CPU 缓存材质、18 个虚构应用；脚本以约 120 Hz 在搜索框、侧栏及应用网格间移动。两版各收到 712 次脚本移动，连续移动段为 6 秒，其余采样段为 2 秒。数值由进程全部线程的 CPU 时间计算，100% 表示占满一个核。

| 状态 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 菜单关闭 | 0.00% | 0.00% |
| 打开后鼠标静止 | 1.50% | 0.50% |
| 连续移动鼠标 | 68.31% | 13.49% |
| 移动停止、高光收敛后 | 1.00% | 0.00% |
| 再次关闭 | 0.00% | 0.00% |

移动段降低约 80.3%。这是本轮脚本压力路径的前后对比，与用户原来约 31% 的日常移动路径不同，不能直接拼接成同一组数据；也不代表所有硬件、真实 GPU 会话或鼠标路径都有相同绝对占用。2 秒窗口的 0% 是采样结果，不是永久零消耗保证。

复现时在仓库根目录执行，将两个占位路径替换为实际二进制路径：

    xvfb-run -a -s '-screen 0 1920x1200x24' dbus-run-session -- \
      python3 apps/ukui-kaishicaidan-v2/tests/pointer_cpu_benchmark.py \
      /path/to/before /path/to/after --output /tmp/launcher-pointer-cpu.json

脚本使用标准库 ctypes 调用 libX11，不依赖 python3-xlib。结果保存在 `/tmp/ukui-launcher-pointer-cpu.json`，原始测量和桌面截图不入库。

## 打开终端

桌面空白处菜单在“打开文件管理器”正上方增加“打开终端”。优先使用系统 `x-terminal-emulator`，再尝试 Mate、GNOME、Konsole、Xfce、Xterm；桌面目录可用时作为工作目录，否则使用用户主目录。直接传递程序与参数，不拼接 shell 命令；没有可启动终端时给出提示。

## 回归结果

- 开始菜单 `launcher-pointer-{1,1.5,2}` 与 `launcher-removal-query-{1,1.5,2}`：6/6 通过。
- 新重绘回归检查静止停止绘制、子控件移动、应用图标不重复绘制、事件合并、材质缓存、范围受限、键盘输入，以及隐藏/换肤/重开后的动画状态。
- 在三个缩放比例下对比真实 X11 窗口的局部重绘与强制完整重绘，覆盖两角与侧栏；逐像素各通道差异允许 Qt 抗锯齿舍入的 2/255，原来遗留的搜索框高光超过此容差并被用例发现，修正后通过。
- 150% 原有开始按钮集成检查通过，覆盖面板启动/移动/替换、鼠标、Win 键及正常退出；实际应用右键来源查询采集 85 个几何样本，始终只有一种位置和尺寸。
- Fences `desktop_menu-shortcut_{1,1.5,2}` 与 `desktop_settings-center_{1,1.5,2}`：6/6 通过。实际桌面菜单触发隔离的终端替身，核对相邻菜单位置及进程工作目录。
- 主程序编译、Python 基准脚本语法检查及 `git diff --check` 通过。本轮没有重新执行全仓 GPU 测试。

同时修正文档中的 Peony 模糊兼容依赖：当前实现通过标准库 ctypes 使用 libX11，无需 Python Xlib。
