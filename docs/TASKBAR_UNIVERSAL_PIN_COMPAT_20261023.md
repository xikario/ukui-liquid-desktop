# 应用窗口通用固定能力（2026-10-23）

基线：b2ec9015f422d8bcbb721d9153a94a8e93888944。以下 OEM 和 X86 真实桌面验收为补丁提供方记录；本机 ARM 组合验证及追加修复单独列在文末，不将提供方测试计为本机通过。

## 行为

所有由原生 UKUITaskButton 承载的应用窗口右键菜单均提供一个可用的“固定到任务栏”或“从任务栏取消固定”操作，不按应用名称、CPU 架构或 NoDisplay 白名单处理。已有原生固定项被替换为统一操作，其余菜单功能和子菜单保留。桌面背景、托盘等非应用任务菜单不受此模块处理。

- 有可用 .desktop：直接沿用其身份和原有启动信息，包括 NoDisplay=true 的入口。不会修改系统 .desktop 文件，也不会把所有隐藏程序暴露到应用列表。
- 无可用 .desktop：先按窗口类查找已有入口，遵循 XDG 用户覆盖优先级；相同可信度存在歧义时不随意绑定其他应用。
- 查无入口：从同用户运行进程读取启动命令及工作目录，生成持久化启动器。完整保留参数；按照 Desktop Entry 和 Exec 两层语义转义，不经过 shell。优先保留原始可执行程序，处理 APPIMAGE 提供的持久化启动路径。
- 窗口未提供 PID、进程已结束或无法得到启动程序：固定选项仍可点击，提供选择启动程序或 .desktop 的恢复流程。取消选择不修改固定配置。
- 固定/取消固定通过原生任务栏槽函数保存；缺失入口的任务组和现有按钮在操作时关联到同一启动器。失败时恢复原来的关联并提示。

生成文件位于 XDG_DATA_HOME/applications/ukui-liquid-pinned-<哈希>.desktop，默认通常为 ~/.local/share/applications/。文件为用户读写权限，NoDisplay=true，避免新增应用列表项。取消固定不立即删除启动器，因为现有运行窗口可能仍引用它；重复操作复用同一身份。

## OEM 细节

1. 本机 Chrome 被应用服务映射到 com.google.Chrome.desktop，文件含 NoDisplay=true。原生菜单将此标记同时用作隐藏固定操作的条件。修复对所有应用任务菜单统一补齐操作，不再受这个条件限制，也不依赖修正 Chrome 单个文件。
2. 本机 hasPinnedToTaskbar 使用旧配置键查询，固定成功后也可能返回 false。模块读取实际原生任务组的 isPinned 状态，避免误报和重复固定。
3. 隔离实测发现，本机原生固定启动按钮的 clicked 回调引用构造期局部 shared_ptr，重启任务栏后点击可在 UKUITaskButton::execAction / XdgDesktopFile::load 中崩溃。模块对窗口 ID 为数值 0 的固定启动按钮，将 button→group 的该 clicked 连接换为现有 DesktopLaunchCompat 的 GIO 启动路径；其他接收者仍收到 clicked，真正的运行窗口保留原生激活/最小化处理。启动失败会显示提示。也覆盖模块挂载前已经显示的启动按钮。

模块使用 Qt 公共对象关系、元对象槽及运行时导出的原生方法，不读取 OEM 私有字段偏移。没有常驻轮询。

## 支持边界

这是通用任务窗口适配，不代表逐一运行验收了本机全部 108 个应用入口。当前实机覆盖本机 OEM/X11，其他 OEM、Wayland、远程窗口和 AppImage 包未逐一实测。无进程启动信息的窗口通过选择启动程序恢复，不生成无效的占位固定项。自制程序重启所需的外部会话、临时文件或特殊运行环境若无法从现有入口/命令恢复，需要用户提供正确启动器。

## 主线评审后的启动信息修复

- 持久化身份包含有效工作目录及完整转义后的 Exec。复用已存在启动器时也检查两者，拒绝复用内容已不匹配的文件，不覆盖原条目。
- 查找本模块生成的入口时，除窗口类外还要求命令和工作目录相符，避免同类窗口重新选中旧工作区启动器。OEM 应用数据库直接传入已有生成入口时，也在首次固定前进行这项校验。系统提供的正常 desktop 入口仍按原有规则查找。
- 保存可执行程序时保留有效绝对符号链接入口；仅 TryExec 身份比较使用 canonicalFilePath，避免改变脚本入口名或多调用名程序行为。
- 新增实际 GIO 执行回归：相同命令从不同工作区启动、生成入口的命令/目录隔离、符号链接脚本实际收到的入口路径。

本轮不自动迁移或覆盖用户已固定的旧启动器，不替换运行中的任务栏。
