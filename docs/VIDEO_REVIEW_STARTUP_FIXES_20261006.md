# 视频壁纸评审核验与登录过渡修复

核验时间：2026-10-05 至 2026-10-06（上海时区）。基线为 `0b546ba`。本轮已编译并安装到本机，未提交、未推送 Git。

## 已修复

| 项目 | 核验与最终行为 |
| --- | --- |
| 预览被第二个实例覆盖 | 删除画布中隐藏的 `VideoWallpaperPreview`。播放状态通知不再触发预览文件检查和随机抽帧。设置页负责预览；防抖到期再次检查缓存，保存通过锁与原子清单提交，已有有效缓存直接采用，保持确认时的三帧和时间点。 |
| 无首帧时出现深色过渡层 | 静态壁纸、首帧缺失、缓存身份变化时不创建过渡层，取消 `#101827` 纯色遮挡。实际测试前用户处于静态模式，旧程序仍持有这层，确认存在异常过渡来源。 |
| 隐藏的全屏过渡层占内存 | 过渡层改为临时堆对象。画布首次可见绘制后延后约两帧销毁；另有 15 秒释放兜底。`--hide` 不读取首帧、不构造此窗口。 |
| 映射与交接空档 | 有缓存时等待过渡层绘制并暴露，最多等待 150ms，之后才构造画布；通过桌面层重排请求置于其他桌面上方。画布 Paint 之后才开始释放计时。 |
| 视频子窗口先显示黑底 | 子窗口先映射但保持空裁剪，允许 OEM 驱动初始化；首个硬件视频帧准备完成才开放裁剪区域。原分辨率、帧率和 VAAPI 路径保持。 |
| 桌面层纠正过重 | `DesktopLayerWatch` 使用持久 X 连接，只订阅根窗口属性事件、处理堆叠列表变化。纠正只发送桌面层重排，不调用 `showAndActivate()`，不发出设置刷新信号。100ms 合并、至少 500ms 间隔，持续冲突退避至 8 秒。移除登录后 0～13 秒的六次定时重试。 |
| Xlib 宏泄漏 | 实现移到 `.cpp`，公共头文件不再包含 Xlib。 |
| 子组件销毁后的遮罩记录 | 改用 `QObject::destroyed` 清理记录和监听集合，并安排几何更新。 |
| 隐藏后显示的画面跳变 | 主动隐藏 Fences 后重新显示，先精确跳回 0 秒，待新帧完成才显示视频。普通窗口遮挡恢复继续当前位置。两种情况保留同一个播放器进程。 |
| 自启动重复探测 | `--autostart` 跳过 launcher 的 gdbus 预检查；主程序原有的 D-Bus 服务注册保证单实例。普通设置、隐藏等入口仍联系已有实例。 |
| 遮挡查询往返 | 缓存外国窗口的类型、状态、桌面、整体透明度，PropertyNotify 时失效；窗口退出时清理，几何仍实时查询。 |
| X 错误被吞 | 播放器输出前五条 X 错误编号、请求、资源 ID；C++ 控制器转记这些有限诊断，避免无界日志。 |
| 缓存累积和高 DPI | 确认视频时保留当前与上一视频的缓存目录，跳过非受管目录和符号链接；新三帧提取为最大 640×360，显示按 DPR 缩放。旧版 320×180 缓存继续兼容，不为升级分辨率重新随机抽帧。 |

评审中的一项推断需要更正：Qt 5 的 QWidget 析构确实会发送 `QEvent::Destroy`，原分支并非必然失效。[Qt 5.12 官方实现](https://github.com/qt/qtbase/blob/5.12/src/widgets/kernel/qwidget.cpp) 在析构路径创建 Destroy 事件并调用 `QCoreApplication::sendEvent`。本轮仍采用 destroyed 信号，使记录清理直接依赖对象生命周期。

## 回归证据

编译 `ukui-fences` 和 `fence-glass-test` 成功。以下八项 CTest 全部通过，耗时约 27 秒：

- `desktop_video_trial`：真实 FFmpeg 三帧抽取；等待中的第二预览采用已确认缓存且清单不变；新缓存实际像素 640×360；当前/上一缓存保留；新建、销毁、替换子组件和遮罩变化的真实播放器几何消息。
- `desktop_startup_wallpaper`：无图不显示深色层；有图已绘制；交接后对象销毁；画布先准备壁纸和实际玻璃；主动隐藏有效。
- `smart_space_startup_async`、`desktop_monitor_placement`。
- 设置中心 1 / 1.5 / 2 倍缩放三项。
- `video_wallpaper_geometry`：11 项 Python 几何、合并遮挡、滞回、隐藏恢复判断测试。

另验证 launcher 的两个分支，以及实际重复运行 `--autostart` 后 D-Bus PID 不变、组件布局不变。

本机使用用户提供的 `【哲风壁纸】人物剪影-开阔-旷野.mp4` 实测：3840×2160、60fps、VAAPI，采样显示约 60.001fps、零报告掉帧。主动隐藏/恢复后位置为 0.033 秒；普通遮挡恢复保持原位置。视频循环、隐藏和窗口遮挡期间 `fenceGlassBuilds` 均为 15，没有随视频帧重建玻璃。

额外覆盖快速切换：在 100ms 事件合并期间先隐藏、30ms 后显示，即使尚未进入暂停状态，也会补做回到首帧和重新开放裁剪。实际连续十次切换，播放器 PID 保持、位置均为 0.033 秒、XShape 有效范围均非空。还验证了最初处于隐藏状态时启动播放器，首次显示同样回到首帧。

受控窗口测试先移开现有普通窗口，并核对测试窗口实际尺寸：

| 条件 | 可见面积占视频有效绘制区比例 | 行为 |
| --- | ---: | --- |
| 单个普通窗口 | 32.72% | 播放 |
| 两个普通窗口合并遮挡 | 5.89% | 暂停 |
| 其中一个改为整体半透明 | 66.52% | 恢复播放，证明属性缓存及时失效 |
| 恢复不透明 | 5.89% | 再次暂停 |

实际向 Peony 发送重排请求，观察到其位于 Fences 上方，随后顺序被纠正。全过程普通前台窗口保持在 Fences 上方，焦点不变；主动隐藏后没有被监视器重新显示。

## 资源采样

每种状态采样 25 秒、约每秒一次，读取 `/proc` 进程 CPU 累计时间。下表是**单核百分比**，本机 8 核，换算整机百分比需除以 8。

| 状态 | Fences 平均 | 播放器平均 | Xorg 平均 | KWin 平均 |
| --- | ---: | ---: | ---: | ---: |
| 静态壁纸 | 1.32% | — | 5.11% | 4.19% |
| 视频可见 | 1.20% | 7.43% | 6.51% | 7.79% |
| 普通窗口大面积遮挡 | 0.68% | 0.00% | 0.68% | 0.20% |

视频可见时，播放器 95 分位约 10.99%、峰值 10.99%；暂停时整个 25 秒窗口没有记录到 CPU 时间增长。播放器 RSS 约 144MiB，暂停保留播放上下文；Fences RSS 静态约 524MiB、视频约 604MiB，各采样段内保持稳定。CPU 暂停不代表释放内存或全部 GPU 资源。

资源采样中的测试窗口被 KWin 自动最大化，实际构成大面积遮挡，不能用于证明单窗与双窗的差异。后续受控测试明确取消最大化、设定并记录尺寸，得到上面的合并遮挡结果。资源采样没有录屏；启动录屏单独进行。短时、未隔离其他进程，不作为功耗、温度或旧版与新版的因果对照；遮挡暂停能力原先已有，本轮证明它在缓存优化后仍然有效。

## 启动与安装

静态模式与保存视频模式各进行了实际进程重启录屏（20fps，缩至 1440×900 保存）。检查关键帧，并对两份录屏的全部 180 帧中同一个无遮挡区域扫描纯黑和统一深蓝，均为零检出。视频模式呈现缓存首帧，再交接画布和实际播放；交接后窗口树中只剩一个带 `ukui-fences` WM_CLASS 的全屏窗口，过渡层已释放。窗口树校验排除了 KWin 装饰框，它们也具有全屏几何尺寸。

静态模式一次带录屏的启动跟踪：构造完成 53ms、壁纸解码 237ms、玻璃首渲染 903ms、四个小组件就绪 1013ms、桌面映射 1049ms、智能空间就绪 1730ms。它是热启动观测，不能代表冷登录耗时。

安装前备份目录：`apps/ukui-fences/releases/20261005-231114-before-video-startup-review/`（0700）。安装的二进制、视频辅助程序、launcher 与源构建哈希一致。临时保存视频用于重启测试后，原壁纸设置节逐字恢复，当前仍是原静态壁纸；组件几何和可见状态已核对。

可复核证据位于 `apps/ukui-fences/build/artifacts/video-review-20261005/`：`deployment.json`、`live-regression.json`、`controlled-windows.json`、`office-samples.jsonl`、`video-startup.json`、`rapid-resume.json`、`initial-hidden.json`、`startup-frame-scan.json`，以及两份启动录屏和各测试脚本。构建/CTest 输出为 `/tmp/video-review-build.log`、`/tmp/video-review-tests.log`，最后的 Python 回归复核为 `/tmp/video-review-python-final.log`。

## 尚需区分的边界

- 本轮没有重启整台电脑；完整冷登录还需下一次实际开机观察。Fences 进程启动前，Peony/显示管理器/合成器的画面交接不能由应用自身覆盖。录屏仍能看到进程重启期间的系统桌面，没有承诺消除这一段。
- 整体透明度属性已处理；逐像素透明的 ARGB 普通窗口仍可能被当成不透明遮挡，保持既有已知限制。
- 原片帧率、分辨率及硬件解码策略保持，未更改 GPU 电源策略、KWin 特效或会话启动顺序。
