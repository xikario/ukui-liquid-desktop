# 系统监视诊断详情改造

日期：2026-10-01。大更新第一阶段，仅修改系统监视；按照用户要求保留本地修改，不提交或推送 Git。

## 行为

- 诊断正文双击展开详情，重复双击复用窗口；编辑布局时不触发。进程诊断仍通过进程右键菜单发起，打开详情不会触发模型请求。
- 默认页为“诊断概览”，显示模型判断、本地规则评级、摘要、关键观察和风险；“详细分析”显示采样范围、瓶颈、依据、短期与长期建议及命令；“采样数据”使用等宽只读 JSON 查看器。
- 顶部显示对象、实际请求模型、开始/完成时间、采样/分析/完成/失败状态。采样进度使用 15 个有效样本的确定进度条，请求模型时使用不确定进度条。
- 命令单独显示为只读代码块，保留用途、适用条件和风险，只提供复制。模型返回的标签、HTML 和链接均按普通文字显示。
- 复制摘要、复制全部、复制命令、复制 JSON 分别工作。复制全部与 TXT 导出保留所有长期建议、风险和命令；JSON 导出是固定请求采样快照，采样尚未完成时是明确标记的本地预览。
- 导出使用 QSaveFile 原子写入、仅当前用户可读写的权限；文件选择器负责扩展名与覆盖确认，不继承液态卡片配色。失败会提示原因。
- 错误卡隐藏旧结论与命令、禁用旧报告复制/导出，提供“检查 API 设置”。清空已结束的诊断时同时清空采样快照、对象及时间。
- 深浅配色跟随监视器皮肤。液态/玻璃皮肤在后台准备壁纸材质，窗口生命周期内复用缓存，拖动、缩放和进度更新不会重复生成材质；窗口关闭后取消结果投递。
- 液态窗的顶部信息与底部提示使用独立阅读底，在纯白壁纸上也保持对比；新诊断因缺少密钥而失败时，清掉上次对象、采样和时间，显示本次请求对象。

## 实现

新增 `MonitorDiagnosisDialog` 专门负责报告视图、复制、导出和材质；`MonitorDiagnosisReport` 负责结构化解析与完整文本表示；`MonitorDiagnosisSnapshot` 表示一次界面状态。`SystemMonitor` 保留采样、进程身份、网络请求和凭据管理职责。

取消原详情窗口 500ms 定时刷新，改为在开始诊断、采样回调、阶段切换、凭据错误、请求完成和显示清空时更新已打开的窗口。完整正文不变时保留卡片、文本选择和滚动；采样 JSON 仅在源内容变化时重新格式化。

提示词新增最多三条 `command_suggestions` 对象，每项包含 `command`、`explanation`、`conditions`、`risk`。兼容旧 `commands` 字段，无法结构化的服务文本在详细页保留完整原文。原有空正文/损坏 JSON/截断时至多一次补取、固定请求快照、凭据释放、过滤与工具调用处理继续保留。
