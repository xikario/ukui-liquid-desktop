# v0.6.0 发布前整体审查 · 2026-10-03

范围包括 Fences 与六类组件、开始菜单、任务栏、公共液态弹窗/材质/后台任务，以及 Peony 模糊兼容和可选电源脚本。承接前一轮未提交的资源优化、公共弹窗、分区设置与图标、窗口标题及智能空间首次收起修复；未覆盖或声称支持所有 OEM 桌面及 Wayland。

## 本轮确认并修复

| 路径 | 问题 | 处理 |
| --- | --- | --- |
| Fences 设置与诊断详情 | 普通任务窗口仍带永久置顶标志，可能覆盖无关应用 | 取消永久置顶；主动打开提升窗口，保留任务栏与最小化能力 |
| 诊断导出 | 文件选择器没有父窗口及诊断身份，可能位于报告后面 | 使用有归属的受保护选择器，补齐监视图标、窗口角色和 desktop 身份；所属报告销毁时安全结束 |
| 开始菜单模态窗口 | Win/再次打开请求可把置顶菜单拉到设置、卸载确认框上方 | 模态期间保持确认框；明确打开请求可恢复最小化的设置 |
| 开始菜单异步结果 | 查询卸载影响或启动操作期间重新打开菜单，后续错误/结果框会被覆盖 | 显示异步结果前收起菜单；回归覆盖延迟返回的替身命令 |
| 开始菜单闲置 | 安全点击检查在没有鼠标按钮按下时仍查找面板和坐标 | 空闲检查提前返回，保留按下后的外部点击判断 |
| 应用图标 | 空文件、损坏图片或目录形式的 Icon 路径绕过后备图标 | 验证实际图像可渲染，失败沿用已有文字后备图标；有效图片保持 |
| 公共对话框恢复 | 窗口管理器恢复时重新抓背景、激活及重播淡入；最小化时丢弃缓存 | 区分主动显示/隐藏与窗口管理器事件，最小化保留材质，恢复复用材质且不主动抢焦点 |
| 关闭与最小化交叠 | 淡出期间最小化会清空待执行的关闭回调，确认结果丢失并使模态等待持续 | 隐藏时停止淡出并在原生事件之后交付一次受保护的结果；主动重新打开仍取消关闭，过期回调不生效 |
| 公共标题与任务栏设置 | 自绘标题缺少图标，部分宿主没有显式应用图标 | 标题显示适配缩放的图标，使用所属窗口图标或主题后备；面板设置补齐图标并使用普通层级 |
| 已有桌面图标拖放 | 来自另一个受识别桌面目录的图标被按外部文件转移到主目录，后续拖动可能失败 | 已有桌面项目就地定位并避让小组件；回归保留不同桌面目录的情况，测试用户目录完全隔离 |

## 已核验的资源生命周期

指针高光使用有限的事件合并与局部重绘；静止或隐藏后停止。静态壁纸、背景模糊与光学材质复用缓存，不因普通悬停持续重建。音乐音符只在组件可见、已连接且播放时运行；监视可见采样、日历刷新与隐藏状态分别受控。智能空间索引加载在后台，首次收起完成布局后读取锚点，不加常驻轮询。

本轮对已优化的本机版本与 0.6.0 做一次隔离对照：150% 缩放、CPU 缓存材质、120Hz 脚本鼠标，按单核进程 CPU 计。关闭、移动停止后和再次关闭均为 0%；连续移动分别为 16.15% 与 16.98%，静止为 0% 与 0.5%。这只能用于核对是否持续空转，短样本不支持声称本轮再次降低了移动时的平均 CPU；不能与真实桌面的其他时段直接比较。

开始菜单仍保留可见期间每 160ms 检查原生按钮状态的外部点击后备。这次减少了空闲分支的面板与坐标查询，没有新增 XRecord 全局鼠标监控。非常短的点击可能落在两次检查之间；不能把本轮修改描述为消除了全部轮询。

沿用既有折射、色散、高光、开合动画和音符参数。画面保持的回归针对光学输出、缓存重用、高光损伤区域和动画完成，不把单次采样写成长期性能保证。窗口管理器恢复事件的语义参考 [Qt QWidget showEvent](https://doc.qt.io/archives/qt-5.15/qwidget.html#showEvent)，并在当前 Qt 5.12 的实际事件路径核验。

## 验证与发布证据

三个应用及各自测试目标均完成构建。各测试入口取修复后的最新结果，合计 108 项通过、2 项按条件跳过：

| 验证 | 结果与范围 |
| --- | --- |
| Fences 全部 94 项 CTest | 92 通过；2 项 Xvfb GPU 用例因离屏 GL context 条件不满足跳过 |
| 开始菜单全部 7 项 CTest | 7/7 通过，含三个缩放倍率的指针和卸载查询用例 |
| 面板全部 9 项 CTest | 9/9 通过，含窗口、主题、安装事务和登录脚本 |
| 真实显示器的 OpenGL 路径 | Fences 40 项、公共光学 43 项断言通过；开始菜单渲染及异步缓存断言通过；不作为长期 GPU 性能保证 |
| 按钮与 Super 键集成 | 150% 隔离显示服务器下 8 项断言通过 |
| Peony 兼容与电源脚本 | Python 及真实 X11 属性用例通过；电源策略使用模拟，没有修改实际策略 |
| 包装与依赖 | 三应用临时 prefix 安装成功；动态依赖可解析；desktop 文件、版本链接和暂存差异检查通过 |
| 本机安装与窗口冒烟 | 三应用已更新并重载；运行二进制或已加载插件与构建一致；配置、布局、面板与开始按钮位置保留 |

全量回归首先暴露了不同桌面目录图标被实际转移的问题，修复后桌面挂件三倍率及关闭生命周期 4 项复跑通过。最后一轮全量回归中的两项原生框选失败源于测试在异步启动前隐藏图标：启动重新显示的图标被正常选中，导致空白截图基线不成立。修正准备时序后，两倍率框选及图标损伤 3 项复跑通过，保留包括屏幕 y=0 在内的所有原生鼠标起点。以上 92 项通过数是这些入口修复后的合并结果，不声称第一次全量运行无失败。

真实 UKUI 设置窗口检查确认了对应的原生图标、普通任务窗口类型、无永久置顶和无跳过任务栏状态；最小化后通过任务激活恢复，发送显示桌面请求后也可再次激活。该 WM 在显示桌面期间仍将客户端报告为 Normal，检查没有把 Iconic 作为必需条件。开始菜单收到再次打开请求时，设置仍保持前台。诊断导出归属和图标、确认/取消与最小化交叠的结果交付由实际 Qt 模态循环回归覆盖。智能空间收起前后保持 `(0,517)`、`52×52`，没有重启整个系统。

原始证据保存到被忽略的 `apps/ukui-fences/build/artifacts/release-v0.6.0-20261003/`，包括各测试日志、隔离 CPU 对照、原生窗口属性及部署哈希。发布仅收录源码、资源、测试及说明；不收录个人分析文稿、构建/部署备份、凭据、个人索引数据和真实桌面截图。提交与 `v0.6.0` 标签指向同一版本；远端 CI 的状态以 [GitHub Actions](https://github.com/xikario/ukui-liquid-desktop/actions) 为准，本机结果不替代远端结果。
