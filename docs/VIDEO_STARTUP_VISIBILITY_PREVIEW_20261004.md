# 视频启动过渡、可见面积暂停与持久动画预览

## 最终行为

- Peony 继续运行，不杀进程、不取消映射、不修改其壁纸或自动启动。Fences 进程启动后先显示属于自身的桌面过渡层，已有缓存时使用视频首帧。主桌面使用同一首帧准备材质，随后恢复视频；去掉原先固定 500 ms 延迟，避免再次解码首帧和重复重建同一背景材质。
- 通过根窗口层级事件检查是否有其他 DESKTOP 窗口盖到 Fences 上方，发生冲突才重新请求桌面层顺序。不会提升到普通应用/任务栏上方；手动隐藏时停止纠正，退出/崩溃后自身窗口由 X server 清理，系统桌面正常露出。
- 登录会话尚未执行 Fences 的阶段无法由应用自身遮挡。实机暖启动截图在进程开始后约 0.275 秒仍捕到系统桌面，下一帧已为缓存视频画面；本轮没有重启系统或声称登录全程零闪屏。第一次尚无视频缓存时仍使用安全回退，不能保证完全跳过静态准备阶段。视频第一帧到开始运动仍需初始化时间，但不再先显示无关图片。
- 在前、中、后三个时间区间各随机选一个目标，提取附近关键帧；确认视频后自动保存三张 PNG 和时间点，设置页按 900 ms 间隔循环显示。使用原生图片轮播，不增加持续视频解码器，也不依赖 GIF 编码器。关闭/隐藏预览停止定时器。再次打开或重启直接使用保存结果；文件路径、大小、修改时间变化时重新生成。长 GOP 或近似静止的视频可能出现相似帧。
- 缓存放在 `QStandardPaths::AppLocalDataLocation/video-previews/v2-<sha256>/`，当前目标机对应 `~/.local/share/kylin/ukui-fences/video-previews/`。目录仅用户可访问，图片和清单使用原子保存，缓存不会改变原视频或将素材加入 Git。

## 性能建议处理

| 建议 | 处理 | 边界 |
| --- | --- | --- |
| 多窗口合并遮挡 | 已采用：计算实际视频形状的剩余可见比例，低于 10% 暂停、达到 15% 恢复 | 仅计入当前桌面上方、已映射、非隐藏、未设置透明度的普通窗口；排除桌面/任务栏/菜单；重叠不重复扣除。阈值内可见的小片视频会暂停，这是有意的节能取舍。复杂区域超过 4096 段时保守继续播放。 |
| 简化 mpv GPU 渲染 | 已采用 `gpu-dumb-mode=yes`、bilinear 三种缩放、关闭 linear-downscaling/dither | 目标机 libmpv 0.32 实机通过。原分辨率/帧率不变，但不声称与原渲染逐像素一致，其他驱动需要各自验证。 |
| 屏幕大小子窗口 + panscan | 已采用 `panscan=1.0`，窗口从约 3204×1802 改为 2882×1802，位置 0,0 | 2 像素补偿继承现有 Qt/X11 桌面边界处理。子窗口面积减少约 10%，不等于 GPU 总负载必然等比例减少。 |
| 任务栏下方静态 | 未采用 | 缺乏单独 KWin 模糊耗时证据；遮掉任务栏附近视频可能产生静动边界、任务栏移动和自动隐藏问题。 |
| 删除 Paint 监听 | 改为比较遮罩和框选区域，仅变化时调度几何计算 | 保留非 Resize 的 mask 变化兼容，时钟/监控普通重绘不再反复遍历全部子组件计算区域。 |
| C++ 重写 Python | 不做 | Python 封装调用 libmpv，线程开销主要属于播放器/驱动；进程 CPU 不能等同解释器耗时。 |

监视器 TOP 5 的 CPU 是单核口径，8 核机上 10.8% 约占整机容量 1.35%；顶部总 CPU 是整机口径。用户给出的线程分布可作为线索，不把它当成本轮重新采到的线程测量。Xorg/KWin 还会受到前台程序、驱动和合成策略影响，不能断言全部来自壁纸或一定无法通过渲染改变。

## 验证与结果

同片源 `像素风格-光影-冒险`，3840×2160 / 60 fps，桌面可见，前后各 65 秒采样，去掉前 5 秒：

| 指标（整机 CPU 百分比） | 旧版 | 新版 |
| --- | ---: | ---: |
| Fences + 播放器 + Xorg + KWin + 驱动线程 | 3.506% | 2.962% |
| 播放器进程 | 1.141% | 0.869% |
| 驱动线程 | 0.524% | 0.146% |
| Xorg | 0.788% | 0.790% |
| KWin | 0.922% | 1.025% |
| Fences | 0.132% | 0.132% |
| 整机所有进程 | 7.685% | 6.771% |

本轮桌面组下降约 0.54 个百分点（相对约 15.5%），主要来自播放器/驱动，Xorg/KWin 没有一致降低。两段记录均 playing、60 fps、采样内丢帧计数 0。该对照是多项改动的组合、一次短测且后台未完全隔离；没有测瓦数、声音或热稳定温度，不能据此保证长期节能幅度或整机增量低于 5%。保频配置仍为之前的 600000 下限，未调整最高频率。

实机遮挡验证使用两个固定尺寸普通窗口（每个约屏幕高度 55%，均未最大化）：单窗剩余视频区域 54.27% 时继续播放，两窗合并剩余 0.63% 时暂停，撤掉一窗恢复播放，全部撤掉恢复 100%，全程同一播放器。前几次测试被 KWin 自动放大成全工作区，不作为多窗成功证据；修正固定尺寸后通过。

实机向 Peony 发送桌面层置顶请求后，Fences 自动恢复上方顺序；显式隐藏两秒内保持隐藏，切回后正常播放。暖启动过程中组件几何/显示状态保留。实机预览截图确认缓存动画加载；测试覆盖保存后重开不依赖 FFmpeg、可见动画切帧、隐藏后停止、首帧缓存先于初次桌面映射。

9 项相关 CTest 通过；最后一次去除重复材质更新后再次通过视频、启动壁纸、几何三个针对性测试。Python 测试覆盖 10 个场景，包括重叠扣除、屏外裁切、多个视频区域、空区域及暂停回差。原帧率和编码校验仍保留。
