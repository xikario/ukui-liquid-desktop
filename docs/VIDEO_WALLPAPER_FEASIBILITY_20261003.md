# 视频壁纸可行性与资源测试 · 2026-10-03

**结论：可行，但低占用依赖实际硬件解码、显示路径和暂停策略。液态材质只取首帧是合适的设计；它节省材质更新，并不免除持续的视频解码与显示成本。本轮尚未实现或启用动态壁纸。**

## 输入与环境

用户提供的本地人物剪影风景短片：H.264 High、3840×2160、60 fps、yuv420p，长 4.684 秒，约 13.96 MiB，视频码率约 25 Mbps。测试机器为飞腾 D3000M、8 核 ARM64，现有 Qt 5/Qt Multimedia、GStreamer 1.16.2、libmpv、FFmpeg 运行库可用。

只对指定本地视频进行有界、无声、无网络测试；原文件及桌面壁纸设置保持。本机生成首帧和独立 1080p/15 fps H.264 派生片段用于比较。一次首帧提取约 0.5 秒；派生片段编码约 8.3 秒，两者都是一次性成本，不计为持续播放资源。

## 实际数据

读取测试子进程 /proc 的用户/内核 CPU ticks 与 RSS，每 250 ms 采样。CPU 按单核 100% 表示，例如 159% 约为 1.59 个核。软件解码比较复测时未同时运行构建或回归；其他用户桌面程序保持运行。硬解测试使用同步空输出，单次播放至文件末尾。

| 测试 | 墙钟秒 | CPU 平均 | CPU P95 | CPU 峰值 | RSS 峰值 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| software-4k60-quiet | 8.28 | 158.92% | 187.46% | 187.62% | 179.98 |
| software-1080p15-quiet | 8.27 | 16.08% | 23.94% | 55.85% | 74.64 |
| gstreamer-vaapi-single-pass | 5.02 | 2.44% | 19.94% | 19.94% | 42.08 |

软件解码用 `ffmpeg -threads 2 -re -stream_loop -1 -i INPUT -an -t 8 -f null -`。低帧率版本经过预转码，不能将播放原始 4K60 后再丢帧视为相同的解码节省。

硬解用本进程环境 `LIBVA_DRIVER_NAME=ftd330 GST_VAAPI_ALL_DRIVERS=1`，管线 `filesrc ! qtdemux ! h264parse ! vaapih264dec ! fakesink sync=true`。成功退出，驱动记录解码 281 个 command buffers。默认 FFmpeg VAAPI 设备探测曾失败；显式指定 ftd330 后两个 render 节点均能解码短片，因此不能把默认探测失败解释为硬件不支持。

另一次 FFmpeg VAAPI 循环测试在首轮约 60 fps 正常，但回绕时出现过滤器格式重新初始化错误并退出，约 5 秒。该失败不能计为稳定循环播放成功，也不能用它的低 CPU 作为循环壁纸指标。生产后端须单独验证 seek/flush、重建解码器与连续循环。

**这些结果只衡量解码到空输出，不包含窗口显示、GPU 纹理导入/拷贝、缩放、KWin 合成和桌面交互。样本只有 5～8 秒，并包含初始化，不能据此承诺最终壁纸 CPU 为 2.4%、无掉帧或长期稳定；也没有测量 GPU/VPU 功率。** 原始数据和日志位于本机 apps/ukui-fences/build/artifacts/video-wallpaper-20261003，不提交视频或本机日志。

## 建议实现

1. 保留现有静态壁纸管线：选视频后异步提取并缓存首帧，以源身份/修改时间作为失效条件。将它放入现有 m_wallpaperSourceImage / m_wallpaperCache，供分区、小组件、菜单及弹窗取材质。视频每帧不触发 wallpaperChanged 或玻璃缓存失效。
2. 视频显示使用独立 GPU 视频层，位于桌面图标/分区之下，保留一张静态首帧作为初始化/失败回退。优先试验已证明可解码的 GStreamer VAAPI 路径，随后验证原生表面或纹理导入与 Qt 窗口层叠；Qt Multimedia/libmpv 是可选封装，需要实测实际采用的解码器，库存在不代表默认硬解。
3. 播放后端、驱动选择与环境变量限定在专用工作进程，不全局修改桌面环境或其他播放器。硬解初始化/连续循环失败时回退首帧；避免悄悄退到原片 4K60 软件解码。
4. 低资源默认建议缓存 1080p/15 fps 的无声版本，允许用户选择更清晰/流畅的档位。15 fps 的画面流畅度和 1080p 清晰度低于原片，不能宣传为无损优化；小动作风景片通常适合，仍需用户实看。
5. Fences 隐藏、屏幕锁定/关闭或桌面完全被覆盖时暂停，恢复后继续；状态以事件驱动，避免定时抓屏判断。遮挡/多屏/Win+D 行为必须在目标窗口管理器验证。
6. 循环重用播放器/解码器与有界帧队列，不在每个 4.684 秒循环启动新进程；材料首帧缓存只在更换来源或参数时更新。可提供“仅首帧”作为真正无持续解码开销的档位。

## 开放功能前的验收

分别测静态、1080p15 硬解、原始 4K60 硬解及故障回退，至少连续循环 10 分钟；记录 Fences、播放进程与 KWin 的 CPU/RSS、实际呈现帧率/掉帧、GPU/VPU 指标。覆盖桌面鼠标交互、分区拖动、打开/关闭设置、系统监视和智能空间、Win+D、全屏办公/会议、锁屏、多显示器和后端异常退出。确认静止玻璃区域不会随视频逐帧重绘，隐藏后解码与呈现停止，首帧与循环边界无黑闪，窗口层级、任务栏、图标交互均正常。
