## 六项收尾

1. **任务栏与文档**：包含 PanelBehavior、相关 schema/行为测试，以及 PanelController/WallpaperBackdrop 的集成；三级动态菜单的共享遮罩修复已包含在基础提交。修复说明保留原始验证日期与证据边界。
2. **音乐去重和防抖**：相同元数据不清零进度、不发 Position 查询、不触发音乐卡片更新；同一首歌的标题或歌词修改保留位置。不同曲目的连续元数据在 120 ms 后只解析最终歌词、读取或下载最终封面，并补取一次最终曲目的位置。封面异步回调核对连接和最新 URL，防止旧结果覆盖新曲目。播放状态、音量、定位及能力变更仍即时处理。
3. **减弱动效**：设置变化即时停掉可见音乐卡片的音符计时器及图标点击动画；必要进度更新和音乐播放继续。刷新使用 80 ms 静态闪亮，仅首尾更新，无逐帧动画；正常模式保留原有刷新动画。
4. **LRC 偏移**：offset 是整份歌词的全局声明，位于开头或末尾时效果一致。重复声明以最后一条为准，多时间戳仍展开并按时间稳定排序。
5. **播放器选择**：仅考虑已启用且运行中的客户端。播放中优先，其次暂停，再其次停止或未知状态；同状态按进程启动时间选择最后启动的，无法读取启动时间时按服务观察顺序稳定回退。启用客户端的 PlaybackStatus 通过 D-Bus 事件跟踪，不增加周期轮询；完整元数据和控制仍只接入一个目标。首次查询期间的较新状态事件优先于旧查询回复。
6. **回归与统计口径**：补充重复元数据、同曲信息更新、不同封面突发、实时状态切换、offset 位置和减弱动画回归；重新运行 Fences、面板和共享组件测试。

## 回归发现的额外修复

2 倍缩放下，音乐卡片局部重绘与整张重绘出现最大 6/255 的像素差异，集中在颗粒的裁剪边界。缓存已经带设备像素比，原先再次按目标矩形绘制引入裁剪相关的采样差异。改为以原生设备像素绘制缓存，保留颗粒、清晰度和局部重绘；三档缩放的图像一致性回归均通过，不放宽原来的 2/255 容差。

新增音乐测试同时验证：封面请求取消后再次回到同一 URL 会重试；在切换曲目后，即使 Position 数值与上一首相同，也立即应用，不被去重误丢弃。

## 资源结论的边界

前次报告列出的静态 0.32%、视频启动 0.40%、视频稳定 1.04%，均是各 25 秒窗口中的 **Fences 主进程平均单核 CPU**，不是视频壁纸整体开销，也不是本轮重新测得的改善百分比。必须另外统计视频助手、Xorg、KWin，并考虑 GPU 解码、显存和合成；共享合成器还承载其他应用，不能把其全部开销归因于壁纸。

局部明暗遮罩使用 16×16 设备像素单元：先遍历整张玻璃图汇总亮度，再遍历整图应用遮罩。180×113 只能是特定图像对应的单元网格规模，不能描述为始终只处理这种尺寸的小图。遮罩、颗粒和内侧高光烘焙到缓存，静止时不会新增周期计算；移动、缩放和换壁纸仍会产生缓存重建成本。

此前 9–17 ms / 15–27 ms 的重建日志不能代表完整界面响应时长，旧版小组件日志计时结束后还有对比度计算及可能的色调调整。本轮已将计时终点移到对比度调整完成后，新日志标注 `including contrast`，包含当前同步重建回调的这些处理；仍不包含异步材质准备、事件排队或最终屏幕合成。首次 471 ms 含 GL 初始化，也不能由较低的 CPU 平均值证明没有首帧延迟。短时唤醒次数不是零成本或长期功耗证据。

64 px 噪声贴图本身均值为零，但 RGB 截断后，纯黑/白等极端底色会有不到一个 8 位色阶的平均偏差；这是说明口径修正，本轮不额外改动其视觉强度。天气缓存因无对应组件列为不适用。
