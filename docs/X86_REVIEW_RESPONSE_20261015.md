## P2-1：首次原生 Win 激活

旧实现按“监听器可用”无条件忽略 WinKeyResponse，漏掉启动监听之前的手势。
现在 KeyInterceptor 向适配器报告实际观察到的 Super 按下/松开；
适配器仅在正在处理手势或刚收到松开事件时消除重复通知。
未观察到手势的原生请求延迟 80 ms，允许另一输入连接已排队的记录取消它；
若仍未收到手势则切换菜单。松开后的去重窗口为 250 ms，不阻止新的 XRecord 手势。
XRecord 不可用时，原生请求直接切换。

新增测试使用真实独立 D-Bus 服务激活，从零菜单进程开始；
分别启用和禁用 Xvfb RECORD 扩展，验证第一次 WinKeyResponse 显示菜单。
已有按钮跟随测试扩展覆盖左右 Win、松键前通知、松键后重复通知、组合键附带通知和长按。
真实 OEM 桌面也验证了原生 WinKeyResponse 冷启动及左右 Win 开关，原菜单未出现。
原生接口没有手势 ID，跨连接去重依赖上述时间窗口，不能声称有协议级精确关联。

## P2-2：安装事务与回滚

路由安装器改为可导入的 install 函数：

1. 对全部目标进行类型与父目录权限预检。
2. 加安装锁，备份全部原目标并记录 before.json。
3. 在各目标同目录暂存、flush/fsync，全部准备好后再 os.replace 发布。
4. 发布或后续记录失败时逆序恢复；原来不存在的目标删除。
5. 回滚失败报告具体目标和保留的备份目录，不假报恢复成功。

两个目标无法做到跨目录单次原子切换；该流程处理可捕获的失败，
不宣称断电或 SIGKILL 期间自动恢复。备份会保留用于人工恢复。

## P2-3：符号链接

使用 lexists/lstat 识别目录项，包括悬空链接。
copy2(..., follow_symlinks=False) 备份链接本身，暂存后替换目录项，
恢复也用同目录临时目录项和 os.replace，不写链接目标。
README 补充链接备份的存在判断与保留类型恢复方式。
