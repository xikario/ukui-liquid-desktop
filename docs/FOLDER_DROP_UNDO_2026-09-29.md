# 拖入文件夹后的撤回

用户反馈：在 Fences 把文件夹拖入另一个文件夹图标后，不能撤回。

## 根因与修复

`DesktopIcon::dropEvent()` 调用异步文件转移，完成回调只刷新提示与显示错误，没有登记 `DesktopCanvas` 的撤销栈；原回调还依赖目标图标存活，文件监视器重建图标时可能丢弃回调。

目录图标现在把转移交给稳定的 DesktopCanvas：发起前拍摄源分区和散落位置，完成后仅将实际成功转移的源/目标配对写入 `FolderDrop` 记录。部分失败和取消不登记未完成项目，同目录拖入不产生空操作。目标提示仍用 QPointer 安全更新，目标图标销毁不影响撤回记录。

移动的撤回恢复原路径及原分区，散落图标恢复原位置；文件监视器临时将恢复文件分配到收件分区时，以原归属为准。复制的撤回仅删除新副本。转移仍使用已有后台文件任务，不新增轮询或常驻工作线程。

撤回失败不再丢掉历史：只把失败项目留在栈顶，处理同名冲突或权限问题后可再次尝试，成功项不重复执行。已有同名文件不覆盖。

## 使用与边界

聚焦 Fences 桌面或分区，按 Ctrl+Z；也可使用现有右键“撤回／撤销上一步”。桌面和分区共用最近 50 条记录，仅当前进程有效。本次修复不能补录旧版本已经发生的拖放；重启后的历史持久化不在本次范围内。
