# 原片 4K / 60 fps 视频壁纸试播验证（2026-10-03）

后续已增加保存和随 Fences 启动恢复，并使用第二段视频做性能对照，见 [后续验证](VIDEO_WALLPAPER_SPACE_20261003.md)。下文为会话试播阶段的历史记录。

已在本机安装并运行原片 3840×2160、60 fps 的硬件播放实现。视频不转码、不降帧、不生成低分辨率副本。当前数据证明 CPU 开销明显降低，但**没有证明所有场景始终比静态壁纸多耗不超过 5 个百分点，更没有证明 GPU 和功耗增量不超过 5%**。

## 实现与使用

Fences 设置 → 壁纸与配色 → “试播视频…”选择本地 H.264 MP4；试验入口限制片长不超过 60 秒、已知帧率不超过 120 fps。停止后恢复原图片壁纸。此功能只在本次会话生效，不保存为登录壁纸。

- `VideoWallpaperTrial` 管理独立播放子进程、首帧提取、画布几何与裁剪、状态和失败恢复。
- Python 通过 ctypes 调用系统 libmpv，采用 `vo=gpu`、原生 `hwdec=vaapi`，禁用软件解码回退，不使用 `vaapi-copy`。Python 不逐帧读回、复制或绘制视频。
- 播放层为输入穿透的 X11 子窗口，裁掉 Qt 控件与选择框覆盖区域。视频按屏幕比例填充裁切，保持原片帧率；桌面为 2880×1800，源视频仍为 3840×2160。
- 玻璃材质使用一次提取的首帧缓存，视频循环不触发逐帧玻璃重建。这意味着玻璃内背景不随视频实时变化。
- 完整遮挡工作区、Fences 隐藏、无可见播放区域时暂停；露出后恢复。播放事件由文件描述符驱动，统计每 5 秒一次，暂停时停止统计计时器。接入 ScreenSaver 锁屏信号。
- 本机 OEM 驱动要求先设置 X11 子窗口大小、裁剪并映射，再初始化 libmpv GL 表面。顺序错误会出现“计数器正常但画面黑屏”；已按正确顺序实现，并以桌面实际画面运动验证。
- 硬件解码不可用、播放器退出或初始化失败时结束试播、恢复图片，子进程退出等待有上限。

额外运行依赖：Python 3、python3-gi（GLib/Gio）、libmpv（本机 libmpv.so.1 / 0.32）、FFmpeg/ffprobe、X11/Xext 和 VAAPI/OpenGL 互操作驱动。主应用不增加 libmpv 编译链接依赖。仅在匹配 `ftd330` 设备时为播放子进程设置对应 VAAPI 驱动名，不修改系统驱动或全局电源策略。

## CPU、内存与帧率测量

环境：飞腾 D3000M，8 个逻辑 CPU，ARM64，UKUI X11 / KWin，FTG340 图形驱动，2880×1800 @ 60 Hz。片源为本地 4.684 秒 H.264 4K60 视频，循环播放。

采样每秒读取 `/proc/stat` 与进程 ticks/RSS，汇总 Fences、播放器、Xorg、KWin、`ftg340_deamon/0-0`；各进程单核百分比之和除以 8，得到其占整机 CPU 的比例。统一剔除前 5 秒，以下视频区间全部处于 `playing`，不会将暂停时间计入有效播放平均值。

| 样本 | 有效时长 | 桌面进程 CPU / 整机 | 原始整机 CPU | 播放器最大 RSS |
| --- | ---: | ---: | ---: | ---: |
| 静态初测 | 25 秒 | 0.289% | 2.239% | 无 |
| 原片 4K60 初测 | 25 秒 | 3.944% | 10.801% | 144.5 MiB |
| 原片 4K60 复测 | 55 秒 | 3.111% | 7.262% | 160.8 MiB |
| 原片 4K60 长采样 | 85 秒 | 6.156% | 9.906% | 144.0 MiB |
| 相邻对照：静态 | 30 秒 | 1.864% | 10.924% | 无 |
| 相邻对照：原片 4K60 | 45 秒 | 3.101% | 7.350% | 143.6 MiB |

相邻对照的桌面进程 CPU 差为 **+1.237 个百分点**；早期两次视频对静态初测分别为 +3.655 和 +2.822 个百分点。长采样相对静态初测为 +5.867 个百分点，不能忽略这个较高样本或宣称固定上限已达标。

Xorg、KWin 和内核 GPU 线程也处理其他应用的工作，本机测试期间仍有其他应用活动，因此上述差值是桌面进程组的观测差，不能全部归因于视频。整机原始 CPU 也明显受其他任务影响；最后一组视频总 CPU 比静态低不代表视频节省了整机 CPU。本次没有隔离其他应用，也没有设置 CPU 硬限额。

最终与长采样状态均报告：原片 60 fps、估算解码 60 fps、显示刷新约 60.000958 Hz、解码丢帧/渲染丢帧/延迟帧均为 0。已用两张实际桌面截图和局部图像差分确认画面运动；这些是播放器计数器与抽样视觉证据，不是独立逐帧扫描输出测量。

GPU 仅能读取频率，静态与视频均观察到 600–800 MHz；没有可用 GPU 利用率或功耗计数器。RSS 不包含所有内核或 GPU 显存分配，不能当作全部额外内存。
