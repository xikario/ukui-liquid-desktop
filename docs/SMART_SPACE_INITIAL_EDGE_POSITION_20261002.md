# 智能空间首次收起位置修复 · 2026-10-02

## 问题与根因

上一轮已在本机记录：首次收起入口位于 Y=457，展开再收起变为 Y=517；展开窗口一直为 (0,448)、763×429。窗口恢复位置正确，错误来自收起入口的定位基准。

收起函数在读取“隐藏”按钮中心点时，可能尚未收到 Qt 的首次布局事件。这个坐标仍是控件构造时的位置；显示、展开完成布局后，同一按钮的实际坐标改变，因此再次收起会跳到另一个位置。

## 实现

在读取锚点前完成控件样式初始化，依次激活智能空间外层布局和左侧操作栏布局，再使用按钮的真实中心点执行现有贴边算法。首次从桌面子组件改为置顶窗口时，当前可用边界也可能改变；收起前用与展开相同的 boundedPosition 校正位置。沿用屏幕边界、原有 32 像素吸附、动画和展开几何保存逻辑，不硬编码纵坐标，不添加延时、轮询或额外事件循环。

## 回归方法

沿用上一轮新增的三档缩放入口，覆盖桌面子组件与置顶窗口、启动后的首次收起、展开/收起循环，以及展开位置和尺寸保持。

额外覆盖父画布尚未映射、首次布局尚未完成就请求收起的顺序。测试使用真正的 DesktopCanvas：普通 QWidget 在采样背景时会触发 grab，提前完成子控件布局，掩盖问题。新用例在修复前稳定失败：两种模式下首次 Y=445、再次 Y=517；该合成时序中外层布局也尚未完成，故首次坐标与本机记录有所不同。没有覆盖固定坐标来绕过失败。

200% 缩放复测还揭示了边界情况：原来的固定测试位置进入屏幕底部 32 像素吸附范围，本就应该吸附，不能要求未经吸附的坐标原样保留。常规用例现使用满足最小尺寸且远离上下吸附范围的位置；另独立验证靠近底部的用例。桌面画布为覆盖 X11 边缘像素，比可用屏幕多 1 像素；置顶转换后的首次收起必须采用转换后的边界，两类用例均要求首次入口与再次入口精确相等。
