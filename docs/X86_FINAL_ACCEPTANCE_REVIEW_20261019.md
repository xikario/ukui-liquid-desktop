## 审查发现和补充修复

### 普通打开器继承管道导致应用退出

原包让 `gio open` / `xdg-open` 使用 Qt 管道输出。打开器结束并删除 QProcess 后，其启动的应用如果继承了这些描述符，延迟写 stdout/stderr 会收到 SIGPIPE。新增真实辅助进程用例，修复前两种输出均失败。

现将 stdout 接到空设备，stderr 接到自动清理的临时常规文件，错误文本最多读取 4096 字节。应用继承的文件描述符不会因管道关闭而触发 SIGPIPE，仍能反馈打开失败。

### 桌面接收者销毁时误终止应用

有些打开器会直接 exec 成为文档应用；由桌面控件持有 QProcess 时，控件销毁会杀掉该进程。新增 exec 型打开器用例，原包确认失败。

现通过独立 shell 监护打开器，只终止监护进程，不终止已经打开的应用。所有文件路径以位置参数传递，不拼入 shell 源码。补充带空格、引号和 shell 元字符的原样参数验证；完成回调先安排进程清理，再调用用户回调，允许回调安全销毁接收者。

### 冷启动测试与新去重窗口不一致

原生菜单去重改为 500 ms，而旧冷启动用例在隐藏后 300 ms 就发送独立原生请求，稳定复现被窗口内去重吞掉。将独立请求放到 600 ms 后，窗口内延迟通知继续由路由测试覆盖；没有通过缩短生产去重窗口规避测试。该时间窗口的输入歧义仍按交付说明披露。

## 交付边界

- 正式居中设置优先调用原生接口。缺少接口时，兼容后端只声明支持 X11 单屏底部面板；默认关闭，按面板保存到 `liquid-panel.ini`，保留整屏底边 strut。多屏、负坐标、顶部/左右、Wayland 等不在支持范围。
