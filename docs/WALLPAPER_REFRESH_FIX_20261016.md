# 刷新桌面丢失自定义壁纸修复（2026-10-16）

## 根因

`refreshAll()` 会重新加载壁纸。此前 layout 只保存图片的原路径，
图片从该位置移走、删除或暂时写坏后，解码失败会直接回退到系统壁纸。
本机配置的 `【哲风壁纸】二次元-冷冽氛围.jpg` 已不存在，实际表现为
自定义壁纸被系统雪山壁纸替换，并非桌面窗口完全没有背景。

## 修复行为

- 成功读取自定义图片后，在 `$XDG_DATA_HOME/ukui-fences/wallpapers/`
  （默认 `~/.local/share/ukui-fences/wallpapers/`）保存独立副本。
- 副本按原始绝对路径的 SHA-256 区分；保留原始文件的编码、尺寸和方向信息。
- 在后台比较和复制文件，通过 QSaveFile 原子提交，内容不变不重复写入。
- 刷新优先读取原图，原图缺失或无法解码时读取对应副本，重新启动也适用。
- 原图恢复或更新后，刷新采用更新后的内容并更新副本。
- 副本保存失败时，同一来源的加载失败仍保留当前已显示的自定义图片。
- 切换到其他路径或系统壁纸时，不沿用上一张图片的内存保护。
- 设置预览支持对应副本，缺失原图时明确提示副本状态。

## 验证

修改前新增用例在删除原图后刷新、重启恢复、损坏原图三项失败；修复后通过。

`desktop_refresh_1`、`desktop_refresh_1.5`、`desktop_refresh_2` 覆盖：
不变壁纸像素和材质缓存保持、同路径更新、删除原图后刷新和重启、
损坏原图回退副本、恢复原图、无磁盘副本的内存保护、不同来源隔离。

关联检查：`desktop_startup_wallpaper`、`smart_space_wallpaper_sync`、
`desktop_video_trial`、`desktop_appearance`。Smart Space 旧测试用固定
500/700 ms 等待异步解码和材质生成，本机可提前采到未完成画面；
将前两次检查改为有 5 秒上限的实际像素条件等待，其余断言保留。

本机部署使用原本的旧版源码树，仅移入本补丁的生产代码，未整体升级桌面。
旧二进制、layout 和启动日志备份位于
`/home/kylinos/apps/ukui-liquid-desktop/backups/20261016-130809-wallpaper-refresh/`。
实机连续三次 F5、两次 refreshAll 后，背景区域像素、壁纸缓存 key
和 Fence 材质生成次数均保持不变。

## 既有文件的限制

修复无法找回已经删除且此前没有独立副本的原图。本机这张旧壁纸需要
重新选择一次；之后成功加载的图片才有可恢复的副本。
本补丁没有改写用户的原壁纸路径或系统壁纸设置。
