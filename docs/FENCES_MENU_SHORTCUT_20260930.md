# Fences 右键菜单快捷键重叠修复（2026-09-30）

## 问题与原因

分区内容区右键菜单第一项“撤回”与 `Ctrl+Z` 重叠。实际旧版绘制记录：
标签横向范围为 `[59,85]`，快捷键从 `76` 开始，重叠约 9 个逻辑像素。
标题栏和桌面菜单因其他条目较长，偶然有足够宽度，不能代替内容区的验证。

Qt 5.12 的 QMenu 在计算公共图标列时仍统计设置了隐藏图标的 QAction；
QStyleSheetStyle 的逐项尺寸计算只增加当前可见图标的宽度。
绘制时却总会扣除公共图标列，导致短菜单的标签空间不足。
Fences 设置 `AA_DontShowIconsInMenus`，因此截图中的图标虽然未显示，仍占用了这列。

此前菜单测试验证尺寸、边缘、状态和键盘行为，没有检查实际文字绘制范围，漏掉了此问题。

## 修复

共享 MenuSkin 按当前菜单字体测量最长标签，统一预留公共图标列和快捷键间隔。
快捷键本身的宽度继续交给 QMenu 计算，保留 QAction 的快捷键、信号、禁用状态和子菜单。
不清空图标，不删除快捷键，不改写业务操作。

动作增删、文字/图标/快捷键变化及字体变化时同步重新计算所需空间；
关闭菜单时恢复原有样式，异步状态项预留最大宽度的接口继续工作。

## 验证

- 新增 MenuTextRecorder，记录 QWidget/QStyle 实际提交的文字绘制范围；
  同时要求标签和快捷键确实绘制、位于动作行内、间隔至少 8 个逻辑像素。
- 实际 FenceWidget 内容区、标题栏及 DesktopCanvas 右键入口，10pt/18pt 字体，
  1×/1.5×/2× 缩放通过；键盘确认准确触发撤回信号。
  同一测试在修复前失败，准确捕获内容区两档字体的重叠。
- 共享菜单覆盖隐藏/可见图标、禁用项、显式制表符快捷键、文字/字体/快捷键变化、
  动作增删。三档缩放及原有共享菜单开关、尺寸稳定回归共 8 项通过。
- Fences 日历、监视器模型菜单及桌面 CPU 集成回归 7 项通过。
- 开始菜单 CTest 11 项、面板相关 CTest 10 项通过。
- 实际开始菜单异步安装来源查询：三档缩放分别采样 49/53/61 帧，
  每档均只有一种原生窗口几何，未恢复菜单伸缩问题。
