## 后续修正：空正文与模型菜单（2026-09-30）

用户反馈真实诊断显示“DeepSeek 未返回有效诊断内容”，同时自动获取的模型名称能够误编辑。

### 正文返回

未保存此前失败调用的原始响应，不能仅据截图判断是长度截断还是服务的 JSON 空响应。已核对代码原先启用高强度思考且 max_tokens=4096；官方 JSON Output 文档也说明有概率返回空 content。因此同时修复请求配置和响应处理：

- 标准诊断使用 thinking=disabled、reasoning_effort=none，让预算用于诊断正文。
- 检查 finish_reason、正文是否有效以及 JSON 是否包含诊断字段。空正文、截断或格式不完整的 JSON 至多重试一次，取消强制 JSON 格式、使用直接中文报告，输出上限为 8192。即使服务标记正常结束，也不把损坏的 JSON 当作成功结果。
- 补取沿用第一次的采样、模型、Endpoint 和密钥，不重复采样，不受等待期间的配置改动影响。
- 重试后仍为空、截断或格式不完整时给出对应原因；过滤、拒绝、工具调用、服务端中断单独说明，不执行任何工具或命令。
- 日志仅记录空正文/截断/JSON 无效标志、思考字符数、token 数和重试次数，不写入密钥、正文或系统遥测。
