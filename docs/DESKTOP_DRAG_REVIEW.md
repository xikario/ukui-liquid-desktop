# 图标拖拽、外观入口与日历同步（2026-09-29）

## 用户反馈与修复

1. “桌面图标样式…” QAction 已创建，但被菜单末尾的重新排列移除。已补回最终菜单，并检查它确实存在于 `QMenu::actions()`，避免仅检查 QObject 子对象造成误判。
2. 录像中重复的图标连同旧壁纸矩形一起残留。原拖放先移动到鼠标处，再吸附到格子，中间执行绘制；现直接落到最终格子。透明 DesktopIcon 移动时显式刷新旧、新两个区域，避免背板拷贝把旧壁纸带到新位置。开始拖动时停止点击回弹动画。
3. 日历右键增加“同步最新农历和节假日”。ICU 在本机计算农历；Python 子进程仅下载公开年度节假日 JSON，校验年份、日期、重复值与休班标记后原子更新。同步包含当前年、所选年、下一年；未发布、格式错误和超时不覆盖旧文件。界面显示结果，不自动联网，不写入或上传系统待办。
4. `layoutLooseIcons()` 曾无条件更新每个图标并整屏同步 repaint。现只在位置或可见性变化时更新受影响的区域；无变化时不刷新。配置了 1500ms 的后备核对定时器目前未启动，因此不能把它描述为现实中的周期性高负载来源。

## 验证与测量

- 视频逐帧复核：`vokoscreen-2026-09-29_13-19-37.mp4`，4.28 秒、25 fps。
- 改动前 30 秒实际会话采样（6×5 秒，CPU 以单核 100% 计）：Fences 0.4%～0.8%，Xorg 约 0.8%，KWin 0%～0.4%。Fences RSS 约 607 MiB；RSS 含图形映射等，不等于本次图标新增内存。
- FTG340 当前频率 600000，最高 800000；这是此前接电最低频率策略，不是 GPU 利用率。可访问的常规驱动接口没有提供 GPU busy 百分比，不能据频率判断 GPU 满载。本次不改调频策略。
- 新增 1×/1.5×/2× 背板回归：移动后的屏幕抓取与完整重绘一致，移动只损伤有限区域。主题插件启动阶段会出现一次全窗口绘制；等启动完成后，测试显式启动后备核对定时器，无变化的连续核对为 0 次绘制。
- 本机相关回归共 22 项：初轮 19 项通过，3 项新空闲绘制断言误计入启动阶段；调整测试等待启动完成后，这 3 项全部通过。原测试里的移动残影检查初轮即通过。
- Python 三个用例覆盖无效数据、HTTP 404、空占位年份、原子写入、失败保留、旧缓存替换和 ICU 农历共存。
- 实际下载：2026 年成功（39 条记录）；2027 JSON 返回空 days/papers，属于尚未发布，未写入缓存。
- 安装后 30 秒采样（通过 `/proc` CPU 时间差计算，非 `ps %CPU` 生命周期均值）：Fences 0.4%～2.19%，RSS 562.6～562.7 MiB；Xorg 1.0%～7.97%，RSS 315.5 MiB。采样未控制用户操作，不能当作严格性能对比，也没有覆盖特定拖动时刻。
- Release 构建及用户目录安装完成，安装二进制与构建产物 SHA-256 一致。重启后通过 D-Bus 核对四个新增小组件可见、智能空间与系统监视可见。启动采用独立进程会话，避免命令结束时带走后台程序。

以上是本机软件回归与空闲采样，不能代替用户在真实 KWin/FTG340 上的拖拽体验，也不证明所有卡顿均由本次修复覆盖。
