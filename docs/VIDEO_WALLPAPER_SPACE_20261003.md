# 视频壁纸保存与太空舱验证（2026-10-03）

后续交互已改为静态／视频类型选择与统一“应用”，并修复 1080P 切换后的桌面层级，见 [2026-10-04 修复](VIDEO_WALLPAPER_DRAFT_DISPLAY_20261004.md)。下文为当轮行为与性能记录。

本轮将视频壁纸从会话试播改为可保存、随 Fences 启动恢复的选项，并保持原片 4K / 60 fps。验证片源为用户指定的“太空卧室-太空舱”本地 MP4：H.264、3840×2160、60 fps、26.134 秒、48,108,851 字节。此前“人物剪影-开阔-旷野”为 4.684 秒 4K60。

## 使用与恢复行为

Fences 设置 → 壁纸与配色 → **选择视频壁纸…**。首帧显示后，只有实际硬件播放器确认完成首帧播放，才保存选择。媒体探测、文件选择成功不等于保存成功。

- 配置键为 `wallpaper/videoPath`，写入现有 Fences 用户配置。
- 启动先准备原图片、桌面和小组件，再尝试恢复保存的视频；不会为等待视频而阻塞桌面首次显示。
- 文件失效或硬件播放失败时恢复原图片；保留上次保存的视频路径，下次启动尝试一次，不后台无限重试。
- **恢复图片壁纸**停止视频并清除保存选择，下一次启动不再播放视频。应用图片壁纸设置也会取消视频选择。
- 单纯退出 Fences 不清除保存的视频。
- 原有 `startVideoWallpaperTrial` / `stopVideoWallpaperTrial` D-Bus 接口仍用于会话预览、A/B 测量；它们不改变保存选择。正式设置使用 `setVideoWallpaper` / `disableVideoWallpaper`。
- 状态接口补充 `savedPath`、`persistent`、`currentIsSaved`、`saving`、`hardwareReady`，区分保存选择、当前播放与异步验证。

仍采用独立 X11 视频层、VAAPI 硬件解码与 EGL/GPU 输出，保持原片分辨率和帧率，无音频；玻璃背景取首帧缓存。没有逐帧 CPU 读回、转码降帧或修改全局显卡电源策略。当前限制为本地 H.264 MP4、时长不超过 60 秒、已知帧率不超过 120 fps；完整依赖和历史实现见 [首轮记录](VIDEO_WALLPAPER_NATIVE60_20261003.md)。

## 本轮优化与路径选择

缓存 X11 Atom，避免每次遮挡判断反复同步查询；窗口事件按 100 ms 合并一次遮挡检测，不逐事件扫描所有窗口，也不采用固定轮询。原片播放计时不受该窗口状态检测合并影响。

测试了 `vo=gpu` 与 `vo=vaapi` 两条硬件输出路径。直接 VAAPI 输出能够显示正确运动画面，但交替样本没有显示稳定 CPU 收益，因此最终保留 EGL/GPU 路径。没有为了压低数字而降帧、降低片源分辨率或绕开桌面合成器。

| 路径（各 45 秒有效区间） | CPU 均值 | 单秒峰值 |
| --- | ---: | ---: |
| GPU 路径第 1 轮 | 2.946% | 3.645% |
| VAAPI 直接输出 | 3.117% | 4.135% |
| GPU 路径第 2 轮 | 2.983% | 4.258% |

## 测量方法

目标机器为 8 核飞腾 D3000M / ARM64 / UKUI X11 / FTG340，显示器 2880×1800 @ 60 Hz。

每秒读取 `/proc` CPU ticks / RSS，CPU 以整机 8 核总能力归一化。桌面进程组包括 Fences、独立视频播放器、Xorg、KWin 与 `ftg340_deamon/0-0`。除另行标注外剔除最初 5 秒，按 `playing` / `paused` 状态检查样本。单秒峰值不是瞬时硬件峰值，也不是所有可能场景的理论最大值。

桌面进程组包含其他应用在 Xorg、KWin 和驱动上的共享开销。测试没有关闭用户应用，窗口活动和后台任务可能影响测量，因此“视频减静态”的差值只能作为当前桌面条件下的观察，不是严格因果隔离。人工窗口动画的自身进程不计入桌面组，其合成和显示开销会计入。

## 最终实测

下表是桌面进程组占整机 CPU 的比例（不是视频独占，不包含模拟计算任务进程本身）：

| 场景 | 有效区间 | 均值 | P95 | 单秒峰值 |
| --- | ---: | ---: | ---: | ---: |
| 静态桌面 | 40 秒 | 0.294% | 0.611% | 0.611% |
| 太空舱连续播放（总时长 6 分钟） | 355 秒 | 3.025% | 4.011% | 6.185% |
| 静态 + 移动/动画窗口 | 40 秒 | 1.914% | 2.197% | 2.438% |
| 太空舱 + 移动/动画窗口 | 40 秒 | 4.676% | 5.114% | 5.609% |
| 太空舱 + 两条 CPU 计算任务 | 40 秒 | 4.517% | 6.789% | 7.407% |
| 完整遮挡，视频暂停 | 25 秒 | 0.308% | 0.611% | 0.612% |
| 隐藏 Fences，视频暂停 | 25 秒 | 0.078% | 0.245% | 0.245% |
| 遮挡/隐藏后恢复 | 40 秒 | 3.214% | 4.126% | 4.265% |
| CPU 负载结束后 | 25 秒 | 4.076% | 4.967% | 4.981% |

连续播放相对静态增量 **+2.732 个百分点**；同样的窗口移动/动画场景增量 **+2.762 个百分点**。最终场景中最大的单秒桌面进程组 CPU 为 **7.407%**，出现在两条额外 CPU 计算任务运行时；这不是硬上限，也不是全部由视频产生。

6 分钟连续播放每分钟均值依次约为 2.95%、3.38%、2.89%、3.06%、3.00%、2.86%。播放器 RSS 首分钟峰值约 155.2 MiB，后 5 分钟稳定在 144.3 MiB；没有观察到循环增长。首帧壁纸缓存键与玻璃构建计数在稳态样本中均未变化。完整遮挡和隐藏后的播放器 CPU 均测得为 0。

所有上述视频场景结束时均报告源帧率/估算解码帧率 60 fps、显示约 60.000958 Hz、解码丢帧/渲染丢帧/延迟帧计数为 0。也已通过桌面截图与运动差分确认太空舱画面正常显示。这是播放器计数器和抽样图像证据，不等于独立逐帧扫描测量。

必须保留早期较高样本：本轮优化前太空舱均值 **8.693%**、单秒峰值 **15.116%**，旧视频均值 **6.958%**、峰值 **9.680%**；当时静态均值 1.309%。早期和最终运行时的其他桌面活动并不完全相同，不能把全部下降归功于缓存 Atom 和合并事件，也不能承诺长期永远不超过 5.87%。最终样本支持“正常连续播放平均增量约 2.7 个百分点”，并给出忙碌场景的已观测峰值。

GPU 利用率、显存和功耗没有完整可用计数器，未验证其增量不超过 5%。暂停保留解码上下文/帧缓存，因此 CPU 降到空闲时内存不会同时归零。上述连续验证为分钟级，不是数小时或数天耐久性结论。

最后相邻比较（均为 40 秒有效区间）：旧视频均值 **3.126%**、单秒峰值 **3.774%**；太空舱均值 **3.154%**、峰值 **4.013%**，均为原片 4K60、零报告丢帧。此次相邻样本的新旧开销很接近，不能仅凭码率或片长推断 CPU 一定更高。

上述稳态表剔除了前 5 秒。将启动/切换暖机样本算入，最终连续播放场景的桌面进程组单秒峰值为 **8.375%**，并发计算场景为 **9.229%**。该进程组不包含短暂的 FFmpeg 首帧提取进程，因此不是启动全链路的完整峰值。原始整机 CPU 在两条计算任务场景均值约 32.89%、单秒峰值 40.37%，其中包含模拟计算和其他应用，不能称作壁纸消耗。

## 复现与证据

新增只读采样工具，可从仓库根目录运行，不切换视频、不改变桌面：

```sh
python3 apps/ukui-fences/scripts/benchmark_video_wallpaper.py \
  --seconds 360 --warmup 5 --output /tmp/video-wallpaper-measurement.json
```

工具保存逐秒采样，按播放状态分别报告均值、95% 分位、最大值；`cpuMachine` 均为占整机 CPU 的百分比。更换静态/视频后各执行一次，保持其他桌面活动尽量一致。
