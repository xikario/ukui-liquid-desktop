# 麒麟 V10 任务栏居中兼容核验（2026-10-15）

本文区分本机实测与用户提供的另一台机器记录；没有远程连接 X86 主机或替换其插件。

## 版本对照

| 项目 | 本机 ARM（本轮读取） | X86（用户提供） |
| --- | --- | --- |
| 架构 | aarch64 | x86_64 / amd64 |
| ukui-panel 包 | `3.26.0.0-0k3.21oemccd3000m0.26.u` | `3.26.0.0-0k5.63` |
| `/usr/bin/ukui-panel` SHA-256 | `d17507c2fa3cd53b4dfd4e2b460f718fbe9117a8888eea94b5abf07d75de1fe4` | `3ffc4fef1c862aad4d867d05c0e1efaec57e798f890f30172bf0b9743c76379f` |
| 整条任务栏布局接口 | 存在且已真实验证 | 记录显示缺失 |
| 68% 居中配置 | 会缩短居中 | 用户隔离测试仍为 X=0、宽=1920 |

两个包的版本与架构均不同；跨架构哈希本来就不可据此定位源码差异。当前只能确认宿主能力不同，不能将“X86 不支持”推广到所有 X86 麒麟系统。

## 为什么控件被禁用

当前液态插件通过 Qt 元对象查找 `setAlignment(UKUIPanel::Alignment,bool)` 与 `setLength(int,bool,bool)`。这两个方法让原任务栏负责几何、屏幕工作区、显示器变化与保存。仅有插件构建和 9 项测试通过，不代表特定 OEM 宿主提供这两个方法。

用户已测试真正的 X86 程序：100% 与 68% 居中配置都得到 X=0、宽=1920，且元对象、系统设置和 D-Bus 没有对应入口。这足以说明该安装版本没有已验证的原生整条居中路径；不说明硬件无法实现。

## 可以采取的路线

1. 优先对照 X86 `3.26.0.0-0k5.63` 的实际源码，在同仓库增加针对该宿主的适配。需同时覆盖长度约束、左右/上下对齐、配置保存、工作区预留、多屏和自动隐藏，不能只增加两个空方法。
2. 或使用经隔离验证确实支持这些能力的官方 X86 包。目前没有可确认的候选版本，不能直接推荐某个升级包；ARM 二进制不能装到 X86。
3. 若拿不到宿主源码，可研究独立窗口层的兼容实现，但这是另一项功能工程。必须处理宿主反复复位几何、最小尺寸/布局、原托盘位置、开始菜单锚点、自动隐藏和 `_NET_WM_STRUT_PARTIAL`。定时器反复移动、仅裁剪透明边缘、只重绘居中背景均不能等同于整条任务栏缩短居中。

当前保留能力检测与禁用说明，避免显示一个无效开关。没有向主线加入未经 X86 实机验证的移动窗口或内存偏移补丁。

## 后续提供的最小材料

- 对应 X86 包本身、匹配源码或可访问的包源；`dpkg-query -W ukui-panel` 和程序哈希。
- 宿主 Qt 元对象的方法、属性和对象名；可在隔离显示中通过现有 `UKUI_LIQUID_PANEL_INSPECT` 诊断开关记录。
- 100%、68% 两组真实几何、屏幕工作区、自动隐藏及缩放信息。

这些材料用于选择适配路径。当前主机只有 ARM 宿主，无法替另一台机器完成 X86 正向验收。
