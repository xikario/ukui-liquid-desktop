# 交付验证：任务栏圆角与两个桌面组件

## 已应用

- 任务栏保留原圆角半径，移除外扩逻辑 mask，以最终材质的物理 alpha 覆盖生成 X11 Shape。
- 实机窗口形状范围由 1964×78、偏移 -3/-3 改为 1958×72、偏移 0/0，匹配窗口尺寸。
- 时钟/倒计时和活动统计集成到 Fences，使用共享光学模块，实机均为 GPU 后端。
- 两组件随 Fences 自动启动；位置、倒计时状态与活动数据持久化。保留原智能空间、系统监视状态。
- 活动记录适配实机 org.ukui.ScreenSaver 的根路径、GetLockState 与 lock/unlock 信号。
- 用户插件与二进制已原子安装，并核对运行进程的二进制/映射。系统 /usr/bin/ukui-panel 未变。

## 验证范围

- 面板原四项 CTest 通过；Xvfb X11 的 100%、150%、200% 下通过物理 shape、关闭恢复、缩放、壁纸切换检查。
- 新组件三个缩放比例测试通过；布局改动及本机锁屏协议适配后复测 150% 通过。
- 计时模型覆盖暂停/继续、到点单次触发、状态恢复、跨午夜、同 boot 去重和历史淘汰。
- 原智能空间壁纸、外观功能和液态 smoke 回归通过。
- 原 fence_glass_cpu 的旧菜单断言原先仅允许两个组件，扩展为四项并分别校验启动键后复测通过。
- 使用真实自启动 launcher 进行进程重启，两个新组件恢复，原两个组件仍显示。
- 活动数据在一次进程重启后，累计开机增量和 /proc/uptime 增量完全一致（均为 4480ms）。
- 实机核对任务栏两角截图与新组件截图，位置最终调整到左侧空白区域。
- 未替用户整机重启，也未实际锁住用户桌面；锁屏通知使用隔离 D-Bus 模拟验证，并只读确认实机接口。

## 资源采样

一次 10 秒桌面空闲采样（单核占比）：
Fences 0.7%，ukui-panel 0.4%，Xorg 0.7%。
RSS 为整个进程，分别约 645MiB、260MiB、242MiB，不代表新增组件的增量内存。
该采样不代表所有交互、壁纸重建或系统负载下的峰值。
时钟与活动刷新测试确认不增加材质重建次数。
