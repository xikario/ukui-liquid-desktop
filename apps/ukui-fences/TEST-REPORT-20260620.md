# ukui-fences v0.4.0 合并测试报告

测试环境：银河麒麟桌面操作系统 V10 SP1、ARM64、UKUI/X11、2880×1800、Qt 5.12。

## 合并范围

- 已合入 `ukui-fences-v0.4.0-20260619-stage` 与对应 patch 的功能。
- 采用双桌面层：Peony 原生桌面始终映射在最底层作保底，Fences 在首次映射前声明为 `_NET_WM_WINDOW_TYPE_DESKTOP` 并位于其上。
- Fences 设置 `SKIP_TASKBAR`、`SKIP_PAGER`、`STICKY`、`SKIP_SWITCHER`，不进入任务栏、分页器或 Alt+Tab。
- 不再使用会破坏 KWin 合成状态的 `XUnmap/XMap`。
- 修复壁纸晃动：壁纸按设备像素比预渲染、居中裁切并缓存，重绘时不再重复全屏缩放。
- 修复 150% 缩放下的几何自激循环：窗口几何不再由 `moveEvent/resizeEvent` 反复回写。
- 修复打包图标 `packaging/ukui-fences.svg` 的自循环符号链接。

## 测试结果

- ARM64 Release 构建：通过。
- 动态依赖检查：通过，无 `not found`。
- 最低 GLIBC 符号版本：2.17。
- 空闲 CPU：0%。
- 空闲连续 8 帧：像素差异 0。
- 连续 8 次强制刷新壁纸：像素差异 0。
- 拖动 Fence 期间连续 24 帧：远端纯壁纸区域像素差异 0。
- 30 次拖动事件：布局仅在释放鼠标时提交 1 次。
- 单实例：重复启动后进程数保持 1。
- Win+D 连续 3 次：显示桌面后始终为 Fences；点击 Fences 后 `_NET_SHOWING_DESKTOP` 仍保持为 1，不会弹回普通应用。
- 手动“切换到系统桌面”：Fences 为 `IsUnMapped`，Peony 保持 `IsViewable`；从开始菜单或托盘可立即切回。
- 强制 `SIGKILL` 模拟 Fences 崩溃：Peony 进程与窗口均保持正常，系统桌面立即成为保底显示。
- 锁定 Fence 接收文件：通过；锁定只限制分区移动/缩放，不限制内容整理。
- 桌面散落文件拖入 Fence：通过。
- Fence 内文件拖入另一 Fence 的普通文件夹：通过，源文件实际移动并从原视图清理。
- 桌面散落文件直接拖入 Fence 内普通文件夹：通过，源文件实际移动并从桌面清理。
- Win+D 往返后壁纸未晃动。
- D-Bus 方法：显示、隐藏、编辑、刷新、退出均通过。
- 临时安装目录测试：二进制、launcher、desktop、autostart 和 SVG 均正确安装。
- 开始菜单：用户级 desktop entry 校验通过，UKUI 菜单数据库已识别，菜单启动保持单实例。
- 退出或崩溃恢复：Fences 不影响始终驻留的 Peony 原生桌面。

- 新建普通文件、原子替换保存、桌面内重命名、移出桌面、直接删除均已通过运行态测试，无需重启 Fences。
- 新文件自动进入 Fence 外桌面网格，不改变已有 Fence 的文件归属。
- 已清理不存在文件遗留的散落图标坐标，避免布局 JSON 累积幽灵记录；无变化轮询不会重复布局。
- 用户保存的 `示例文档.pdf` 已在当前 Fences 桌面正常显示。

## 2026-06-24 真实 CSV 不显示问题回归

- 复现文件：`示例收集表.csv`。
- 根因：文件路径与坐标已经写入 `layout.json`，但运行态可能进入“散落图标控件未重新 show/move”的半同步状态；此时文件集合未变化，旧逻辑跳过 `layoutLooseIcons()`，手动刷新也无法把控件重新画出。
- 修复：`refreshDesktopIcons()` 每次桌面对账后都重新压一遍 Fence 外散落图标布局，确保已有坐标的文件也会重新 `move/show`。
- 直接截取 Fences 窗口验证：真实 CSV 已显示在左上角散落图标区。
- 额外测试：新建 `CODEX-FENCES-实时可见性验收.csv` 后实时进入 layout 并出现在 Fences 窗口；删除后 layout 自动清理，测试文件已删除。
- 注意：测试过程中发现系统 `ukui-screensaver-dialog --lock` 会盖住所有桌面窗口；锁屏状态下 root 截图看到的是屏保层，不代表 Fences 内部未显示。
